# rule-check 开发约定

`rule-check` 是本源码仓库随源码发布的独立 Python 只读工具，入口和依赖见本目录的 [README.md](README.md)。本文件只记录该工具特有的边界；源码编程、源码测试、源码文档和工作区测试的通用要求分别按仓库规则执行：

- [编程规范](../../rules/repo/coding/AGENTS.md)
- [源码测试与依赖](../../rules/repo/testing/AGENTS.md)
- [源码仓库文档](../../rules/repo/docs/AGENTS.md)
- [工作区测试与验证](../../rules/workspace/testing/AGENTS.md)

## 工具边界

- 工具必须能在声明的 Python 依赖就绪后单独运行，不导入本仓库的其他 Python 模块，不依赖工作区中其他工具、残留产物或默认目录。
- 运行时只读取调用者显式提供的目标路径和规则检查所需的 Git 元数据，报告只写标准输出；普通运行不创建文件、目录、缓存、日志或报告，不修改、移动、删除、暂存目标文件，也不请求网络。
- 不读取真实个人配置、凭据或个人 `profile` 内容。规则检查可以验证公开示例的结构；发现被跟踪的私人路径时只报告路径，不打开其内容。
- 解释器、工作目录、输入路径和输出重定向由调用者传入，不在源码中硬编码本机路径。源码仓库版本中不包含 `venv`、解释器缓存或个人 profile 数据。

## 事项状态契约

- `tasks` 入口必须先验证工作区、源码仓库和事项目录的完整路径及边界。默认 `<工作区>/docs/tasks` 不存在时报告跳过；显式指定的缺失路径仍报告错误。工具不自动创建目录。
- 只识别精确小写的 `todo/`、`done/`、`drop/` 目录，事项正文的 `状态` 值必须分别为 `todo`、`done`、`drop`。目录或正文使用旧名称、其他大小写或中文别名时报告错误，不读取、改名或迁移。
- `todo`、`done`、`drop` 目录按需存在即可，不要求同时创建，也不要求工作区预先建立 `build/`、`tmp/` 或其他分类目录。
- 事项扫描只读取已识别状态目录中的 Markdown；README 不按事项格式解析。真实项目文档不得作为可修改测试夹具。

## 开发与验证

- 测试只使用合成仓库和合成事项。按仓库测试规则和工作区测试规则，由调用者预先准备工作区内已存在的 `tmp/rule-check/<批次>/`，再通过 [run_tests.py](run_tests.py) 显式传入；测试脚本不会替调用者补建工作区目录。
- 测试、安装和报告保留的位置由调用者明确指定并遵循工作区目录规则。普通校验不需要测试目录；不把真实 `docs/`、真实 profile、个人配置或网络服务作为前置条件。
- 修改后由负责整体任务的代理统一决定是否执行测试。本目录文档修改不要求在此处运行测试，也不触碰 `MaaWW/`、`refs/` 或真实工作区资料。

requirements.txt 中的精确依赖只在依赖变更任务中调整；无关修改不得升级、替换或补充依赖。
