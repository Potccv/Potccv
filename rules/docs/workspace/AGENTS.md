# AGENTS.md — 工作区开发文档

先按[文档位置与适用范围](../AGENTS.md#文档位置与适用范围)确认目标。本文件仅适用于 `<工作区>/docs/`：它位于所有源码仓库之外，与项目目录同级，用于本机开发说明、事项进度与验收记录。下文中的路径均以已确认的工作区为基准，不按当前工作目录推断；这些事项与时间规则不适用于 `<源码仓库>/docs/`。

共同写作和验证要求见[文档与资料](../AGENTS.md)。源码契约、项目架构与正式使用说明按[源码仓库文档](../repository/AGENTS.md)维护；本机资料通过链接引用正式说明，不复制维护项目事实。

## 写作与维护

- 本机现行说明在固定主题文件内原位覆盖更新；用法变化时同步改写正文和示例，不另建日期版、最新版或副本并行维护同一用法。
- 更新后检查旧说明和副本；已过期且被新说明完整替代的文件，在确认仍有效的内容、未关闭事项、授权限制和必要证据已保留后清除，并同步更新导航和引用。历史验收记录与完成事项按各自保留要求处理，不仅凭日期较早就判为过期。

## 资料存放位置

目录分类遵循[目录职责](../../workspace/AGENTS.md#目录职责)，已有同职责目录可沿用，不为统一名称自行全量迁移。同一事实只在对应位置维护，其他文档引用它。

| 本机资料 | 位置 |
|---|---|
| 本机方案、任务操作记录、协作记录、私有运维资料和文字验证结论 | `<工作区>/docs/`，按项目或用途分类；敏感资料不写入公开项目文档 |
| 本机使用版本、任务进展、部署与验证结论、持续授权与限制、交付历史 | `<工作区>/docs/`；持续跟踪的事项按[状态记录](#状态记录)维护 |
| 程序快照、需保留的原始构建或测试证据、交付物及冻结快照 | `<工作区>/artifacts/`，文字说明引用其位置；可再生成的构建输出归 `<工作区>/build/`，短期文件归 `<工作区>/tmp/` |
| 原始素材、数据集和完整原始采集会话 | `<工作区>/data/`；会话内的记录与附件一并保留，不按文件扩展名拆散 |
| 本机复用辅助工具源码 | `<工作区>/tools/`，本机资料引用工具自身的用途和操作说明 |
| 个人配置与凭据 | 按[凭据与发布要求](../../../profile/AGENTS.md#凭据与发布)存放 |

需要从个人配置查找资料路径时，见[个人配置字段](../../../profile/AGENTS.md#字段职责)。`<工作区>/docs/` 保存本机开发说明、事项进度与验收记录，不作为安装包、SDK、工具源码或程序快照的堆放位置，也不要求每个临时文件配备 README。Potccv 约束仓库不集中收纳其他项目的本机资料。

## 状态记录

- 需要交接或持续跟踪的任务按[事项管理](#事项管理)维护唯一事项文件，记录当前使用版本、实际验证范围、待办、持续授权和限制；README、概览和跨事项主题入口只提供导航与关联，不重复维护单个事项的进度。
- 源码、部署和验收状态分别记录最后核验时间；搬移文档不更新实测日期。章节排序、版本号和源码推送均不构成实际部署结果的证据。
- 历史记录保留当时的事实、日期和限制，并链接后续状态入口；阶段证据按[资料存放位置](#资料存放位置)保留。

## 事项管理

本节仅管理 `<工作区>/docs/tasks/` 中的本机事项，不要求源码仓库采用这些目录、状态或时间格式。

- 将交接中的未完成工作按可独立验收的事项拆为文件，默认放在 `<工作区>/docs/tasks/待办事项/`。一个功能或问题对应一个事项，实施步骤使用文件内的检查清单，不为每个小步骤单独建文件；约定、设计依据和操作限制留在对应文档，由事项引用。
- 文件使用稳定且唯一的编号和表达用途的名称，例如 `T001-开发工具独立运行.md`；创建前检查待办与完成目录，避免编号冲突或重复建项。待办文件中的状态为“待开始”“进行中”“受阻”或“待验证”。
- 每个事项写明目标、工作清单、验收条件、当前进展与接续、关联资料；需要其他事项先完成时引用其编号和路径。该文件是对应任务进度和接续信息的唯一来源，不再在总交接或另一份待办清单重复维护正文。
- 实现完成且适用验证通过后，补充完成结果与验证证据，将状态改为“已完成”，把原文件移入 `<工作区>/docs/tasks/完成事项/`，保持编号和文件名，并同步更新导航及其他事项中的路径引用。同一事项不在两个目录中各留一份。
- 时间记录放在事项文档最末端，正文和关联资料均位于时间记录之前。未完成事项保留“创建时间”“最后更新时间”两行；完成时在最后追加“完成时间”，作为文档最后一行。
- 事项时间使用任务所属时区的 24 小时制，格式统一为 `yyyy-mm-dd hh:mm:ss`，精确到秒，不附加时区后缀或毫秒。创建时间固定不变，最后更新时间随正文或状态变更更新，完成时间记录实际达到验收条件的时刻，不因后续归档或移动而改写。
- 拆分旧交接时保留原验证日期、授权限制和未关闭事项；新事项文件的创建时间取实际创建时刻。历史时间无据可查时标注“未记录”，不以迁移时间冒充历史创建、更新或完成时间。

事项文件按以下结构维护，时间占位符须替换为实际值：

```markdown
# <事项名称>

状态：待开始

## 目标
<预期结果>

## 工作清单
- [ ] <实施步骤>

## 验收条件
<可核验的完成标准>

## 当前进展与接续
<已完成工作、阻塞点和下一步>

## 关联资料
<设计依据、相关事项、源码和验证证据的链接>

---
创建时间：yyyy-mm-dd hh:mm:ss
最后更新时间：yyyy-mm-dd hh:mm:ss
```

完成时在文末追加 `完成时间：yyyy-mm-dd hh:mm:ss`，其中时间替换为实际完成时刻；历史完成时间无据可查时使用 `完成时间：未记录`。
