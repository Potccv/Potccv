# AGENTS.md — 文档范围与共同要求

使用本资料维护文档时，先遵循[根目录执行要求](../../AGENTS.md)，再按下表选择适用规则。维护本目录约束时，同时遵循[通用约定文档的维护要求](../AGENTS.md)。

## 文档位置与适用范围

- 先确认当前任务的工作区根、源码仓库根和目标文件的完整路径。源码仓库通常位于工作区内，因此先判断文件是否属于源码仓库；不能仅凭目录名 `docs`、当前工作目录或文件是否被 Git 忽略来确定归属。
- 本文中的 `<工作区>` 与 `<源码仓库>` 表示已确认的实际根目录，不是相对路径的简写；两者内部的 `docs/` 是不同的维护范围。

| 目标位置 | 用途与执行规则 |
|---|---|
| `<工作区>/docs/`，位于源码仓库之外 | 本机开发说明、事项进度与验收记录，遵循[工作区开发文档](workspace/AGENTS.md) |
| `<源码仓库>/docs/`，以及仓库内的 README、模块说明、CONTRIBUTING 和 AGENTS | 随源码维护的项目说明、接口与使用文档，遵循[源码仓库文档](repository/AGENTS.md) |

- 工作区事项的待办/完成目录、文末时间、原位覆盖与过期旧文件清理规则仅在其规定的工作区范围内执行，不自动套用到源码仓库文档。
- 维护一类文档不自动扩展到另一类，不因同名目录而跨范围创建、移动或删除文件。更新通用约束只涉及约束及已授权的入口，不自动修改使用这些约束的项目文档。

## 共同写作与核对

- 同一事实在所属范围保留一个维护位置，其他位置通过链接引用；文档职责分别按上述两份规则确定。
- 上层文档说明直接子目录的用途、适用条件和入口；详细说明归入相应主题，避免在目录页重复正文。
- 文档描述已核实事实，保留条件、授权范围、例外与原验证日期；未提供或未核实的信息明确标注。
- 参考说明按主题组织，操作指南按前置条件和步骤组织；不因搬移、改名或格式调整宣称实现或验证状态已改变。
- 在当前任务范围内新增、移动或删除文档时，同步更新相应导航、约束入口和受影响的引用。
- 文档变更后核对链接、标题锚点与示例，只报告实际完成的验证。

## 交付说明

- 简要说明修改的是工作区文档还是源码仓库文档，并报告实际改动、验证结果和遗留问题。
