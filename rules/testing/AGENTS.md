# AGENTS.md — 测试与验证

使用本资料开展开发验证、测试或清理测试临时文件时，遵循本文件及[根目录执行要求](../../AGENTS.md)。维护本目录文档时，同时遵循[通用约定文档的维护要求](../AGENTS.md)。

开展验证时先读[开发与验证](#开发与验证)和[验证范围](#验证范围)，按需选读用例与执行要求；需要测试临时文件时再读[测试临时目录](#测试临时目录)。

## 开发与验证

- 条件允许时，先在本地验证，再到获准的测试设备核验实际运行情况。
- 涉及 UI 的测试应在用户协作下完成。
- 验证结果按[状态记录](../docs/AGENTS.md#状态记录)记录。
- 验证围绕需求、故障模式和实际改动展开，优先检查最能发现问题的路径；不能仅因程序启动、接口返回成功或编译通过就宣称功能正确。
- 测试必须在适用的授权范围和隔离环境中执行，不对生产设备、真实用户或外部系统制造未经授权的写入、通知、费用或压力。

## 验证范围

| 改动或风险 | 优先验证内容 |
|---|---|
| 文档、注释、纯格式或可逆且影响很小的修改 | 差异、链接、锚点、示例及适用静态检查；不为这类改动专门新增测试 |
| 业务计算、解析、条件分支 | 有意义的输入输出、边界值、异常值及业务不变量 |
| 已确认的功能缺陷 | 可复现触发条件及修复结果；有价值且可稳定运行时补充防止复发的用例 |
| 数据库、文件或外部适配层 | 真实接口语义、约束、事务、资源释放和失败恢复 |
| 公共 API、事件或共享数据格式 | 契约、旧消费者兼容、未知字段或值、超时及重复请求 |
| 并发、重试或状态转换 | 竞态、幂等、取消、部分失败和顺序约束 |
| 权限、身份或敏感数据 | 拒绝路径、越权、跨租户边界及敏感信息暴露 |
| 用户界面和完整业务流程 | 关键用户路径、交互状态及实际支持设备；遵循本文件的 UI 协作要求 |
| 迁移、发布或恢复 | 版本共存、迁移后约束、冒烟检查及实际可执行的恢复路径 |
| 依赖更新或性能调整 | 受影响的兼容行为、构建结果和可比条件下的性能表现 |

- 表格用于按风险选取检查，不要求每次修改执行所有层级。优先复用已有测试，只有缺少必要行为证据时才新增用例。
- 单元测试适合隔离业务规则，集成测试用于验证组件边界，端到端测试覆盖少量关键用户路径；数量和比例由风险决定，不规定固定测试金字塔比例。
- 不编写仅复述实现步骤、只检查模拟对象被调用或只证明常量相等的测试；测试应该能发现有意义的行为变化。调用本身构成契约时，可以验证其必要参数和副作用。

## 用例设计

- 测试名称说明场景和预期结果；准备条件、触发动作和结果断言清晰，失败信息能够帮助定位问题。
- 用例相互独立，可单独运行，不依赖其他测试留下的数据、固定执行顺序或开发者本机状态。
- 结合改动覆盖空值、零值、最小最大值、非法输入、权限拒绝和依赖失败等相关情形，不机械枚举与功能无关的组合。
- 对随机数、时间和外部网络进行适当控制；需要随机测试时保留种子或最小失败样本，确保能够复现。
- 模拟对象用于控制外部边界和故障，不应把待验证的核心行为全部替换掉；数据库方言、约束和事务保证需要在适当真实环境中验证。
- 异步断言使用有界等待和明确完成条件，避免仅靠固定休眠猜测任务已完成。
- 测试数据优先采用小而可理解的合成样本；敏感数据处理遵循[隐私与数据使用](../security/AGENTS.md#隐私与数据使用)。
- 覆盖率只反映执行到的位置，不能证明断言有效。保留项目已有门槛，同时关注关键分支、失败路径和历史缺陷，不以追求百分比为由添加无价值用例。

## 执行与失败处理

- 按项目实际入口执行格式、静态检查、类型检查及必要测试；命令从已有配置和文档核实，不凭空假定存在某个脚本。
- 先运行与修改直接相关的检查，再按跨模块影响扩大范围。必要检查全部通过后，除非有新增改动、失败或未解决疑点，不反复执行同样的验证。
- 失败时先区分功能回归、已有问题、环境缺失和用例不稳定，保存与判断有关的证据；“之前就失败”同样需要依据。
- 不通过删除断言、放宽预期、关闭检查或反复重跑直到偶然通过来掩盖问题。确需调整错误的用例或隔离不稳定测试时，说明依据、影响和后续处理方式。
- 环境不具备时完成可执行的检查，明确尚未运行的项目及原因，不能把未执行写成通过。

## 结果与完成标准

- 完成意味着本次约定的行为有证据支持，适用检查已执行，遗留问题和限制已明确；不以“写完代码”代替验证完成。
- 交付记录说明检查对象、环境、实际执行的命令或操作及结果；需要比较版本或环境时记录对应标识。
- 区分“自动检查通过”“人工核验通过”“未执行”“不适用”和“失败”，避免使用含义模糊的“应该没问题”。
- 测试只能支持实际覆盖范围内的结论。仅本地通过不能表述为已经在目标设备或生产环境验收。

## 测试临时目录

- 测试需要临时文件时，在[工作区布局](../workspace/AGENTS.md)约定的临时文件目录内为本次测试新建专用子目录，按 `YYYYMMDD-HHmmss-测试内容` 命名；日期时间采用创建时的本地时间，测试内容使用简短、可识别的描述，例如 `20261005-153000-接口冒烟测试`。
- 测试通过后，按[状态记录](../docs/AGENTS.md#状态记录)保存必要的验证记录，并及时删除本次测试的临时目录及其中的文件。
- 需要用户手动删除的目录统一加 `!` 前缀，便于按名称升序排列时优先显示；测试已通过的目录同时加 `-PASS` 后缀，命名为 `!原目录名-PASS`，例如 `!20261005-153000-接口冒烟测试-PASS`。已有前缀或后缀时不重复添加。
- 测试通过后的删除操作若被自动拦截，按上述方式标记目录，并告知用户测试已通过但清理未完成，提供实际目录路径，提醒用户手动删除。若重命名也被拦截，保留原名并如实报告实际路径及未能标记的情况。
