# AGENTS.md — 测试与验证

使用本资料开展开发验证、测试或清理测试临时文件时，遵循本文件及[根目录执行要求](../../AGENTS.md)。维护本目录文档时，同时遵循[通用约定文档的维护要求](../AGENTS.md)。

开展验证时阅读[开发与验证](#开发与验证)，需要测试临时文件时再读[测试临时目录](#测试临时目录)。

## 开发与验证

- 在完成当前的编程工作后统一测试。
- 常规自动测试应在声明的依赖就绪的独立检出中可运行，使用仓库样例、合成数据或明确可获得的测试资源，不得将本机工作区私有资料、某次采集会话或未经本次准备的旧产物作为默认前置条件。
- 使用真实本机资料的验收应提供独立入口，并显式传入所需资料；常规自动测试不隐式启用此类验收。输入与产物的存放遵循[目录与文件组织](../workspace/AGENTS.md#目录与文件组织)。
- 条件允许时，先在本地验证，再到获准的测试设备核验实际运行情况。
- 涉及 UI 的测试应在用户协作下完成。
- 验证结果按[状态记录](../docs/AGENTS.md#状态记录)记录。

## 测试临时目录

- 测试需要临时文件时，在[工作区布局](../workspace/AGENTS.md#目录与文件组织)约定的临时文件目录内按任务、批次建立专用目录，默认使用 `tmp/<任务>/<YYYYMMDD-HHmmss-测试内容>/`，不将共享的 `tmp/` 根目录作为测试输出目录；日期时间采用创建时的本地时间，测试内容使用简短、可识别的描述，例如 `20261005-153000-接口冒烟测试`。后续清理及 `!`、`-PASS` 标记仅作用于本次批次目录。
- 测试通过后，按[状态记录](../docs/AGENTS.md#状态记录)保存必要的验证记录，并将必要验收证据、交付物及其路径保存到[目录职责](../workspace/AGENTS.md#目录职责)约定的资料位置，再按[生成与清理](../workspace/AGENTS.md#生成与清理)及时删除本次批次的临时目录及其中的文件；历史资料、用户资料、完整原始采集会话及冻结证据不属于本次清理范围。
- 需要用户手动删除的目录统一加 `!` 前缀，便于按名称升序排列时优先显示；测试已通过的目录同时加 `-PASS` 后缀，命名为 `!原目录名-PASS`，例如 `!20261005-153000-接口冒烟测试-PASS`。已有前缀或后缀时不重复添加。
- 测试通过后的删除操作若被自动拦截，按上述方式标记目录，并告知用户测试已通过但清理未完成，提供实际目录路径，提醒用户手动删除。若重命名也被拦截，保留原名并如实报告实际路径及未能标记的情况。
