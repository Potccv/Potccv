# AGENTS.md — 安全与隐私

使用本资料处理身份、权限、不可信输入、敏感数据或外部集成时，遵循本文件及[根目录执行要求](../../AGENTS.md)。维护本目录文档时，同时遵循[通用约定文档的维护要求](../AGENTS.md)。

先掌握[安全边界](#安全边界)，再按任务读取输入、访问控制、密钥或隐私章节；不同暴露面采用相应措施，不为所有本地工具机械套用完整互联网服务方案。

## 安全边界

- 根据实际场景识别需要保护的数据和操作、潜在访问者、入口及信任边界，优先防范会造成越权、数据泄露、资金损失或代码执行的路径。
- 默认采用最小权限，按环境和用途分配应用账号、数据库账号及访问令牌；正常运行不依赖管理员权限时，不使用管理员账号。
- 访问控制或关键安全校验不可用时，不得降级为允许访问。必要的故障降级不能绕过权限和数据完整性要求。
- 浏览器、移动端、外部 API、消息、文件及数据库中的历史文本，都可能包含不可信内容；不能因为数据已经入库就默认安全。
- 安全措施应落实到真实边界和可验证行为，不能用隐藏按钮、难猜 URL、客户端校验或模糊化代码代替授权。

## 不可信输入

- 在入口验证数据类型、结构、长度、范围和允许值；为请求体、上传、解压、递归解析和批处理设置资源边界。
- 数据库访问遵循[查询与容量](../data/AGENTS.md#查询与容量)；调用命令优先使用可执行文件与参数数组，不把不可信输入拼进 shell 命令。
- 根据 HTML、URL、JavaScript 等实际输出上下文进行编码；需要允许富文本时采用维护良好的净化机制。输入校验、输出编码与 HTML 净化承担不同职责，不能相互替代。
- 处理文件路径时确认规范化后的目标仍位于允许目录内，考虑绝对路径、父目录跳转、符号链接、重解析点及检查后目标变化的风险。
- 用户可控 URL 需要防范服务端请求伪造：按场景限制协议、目标和端口，核验实际连接地址与重定向，不只检查最初的字符串。
- 上传文件按用途核验大小、实际内容类型和访问方式，不仅依赖扩展名或客户端 MIME；不将未经验证的上传放入可执行目录。
- 不对不可信内容使用任意代码求值或能够实例化危险对象的反序列化；配置、模板和插件具有执行能力时应明确其信任要求。
- 含有 AI 或自动化代理功能时，将外部文档、网页和工具输出作为数据处理，不能让其中的指令直接改变权限、触发敏感操作或覆盖可信的任务约束。

## 身份与授权

- 明确认证解决“是谁”、授权解决“能做什么”；每个受保护操作在服务端或实际执行边界检查相应权限。
- 授权落实到具体对象、租户和动作，不能只验证已登录。调用方提交的用户 ID、角色或租户 ID 不能直接作为可信身份来源。
- 使用成熟的身份协议与库，并按照协议验证签名、签发方、受众、有效期及必要的重放防护，不自行设计认证协议。
- 明确会话建立、续期、退出、过期与撤销方式；权限变化后缓存或长期令牌的生效延迟需要符合业务要求。
- 基于 Cookie 的浏览器会话按实际场景设置 `Secure`、`HttpOnly`、`SameSite` 等属性，并处理 CSRF；不能把 CORS 当作认证或通用的跨站请求防护。
- 登录、验证码、找回密码等敏感入口按需求限制频率并防范枚举；兼顾正常用户恢复路径，避免简单锁定机制被用于拒绝服务。

## 密钥与加密

- 源码、示例、测试、截图、日志和错误响应不得包含真实密码、私钥、访问令牌或可直接复用的会话信息；个人配置存放与发布遵循[凭据与发布要求](../../profile/AGENTS.md#凭据与发布)。
- 通过项目采用的秘密管理系统或受保护的配置注入凭据，区分环境和权限；避免把凭据放入 URL 或容易被进程列表、命令历史记录的参数。
- 密钥需要时具备轮换和撤销路径，采用最小有效期及作用范围；不能只设计“如何生成”，忽略“如何失效”。
- 密码使用成熟的密码哈希方案及库推荐参数，并使用独立盐值；不使用明文、可逆加密或普通快速哈希存储登录密码。
- 使用经过审查的加密库和协议，令牌与密钥使用密码学安全随机源；不得自行设计密码算法。
- 需要加密传输时正确验证证书与主机名，不能将关闭验证作为正式修复；本地测试的特殊配置不得意外进入生产。
- 凭据已经泄露时，优先吊销或轮换并核查影响；删除当前文件、加入忽略规则或改写提交历史，都不能代替使旧凭据失效。

## 隐私与数据使用

- 只采集实现功能所需的数据，明确用途、访问范围、保留期和删除机制；适用的法律、合同与用户选择由所属项目确认，不凭空宣称符合某项法规。
- 日志、分析事件、导出、缓存、备份和错误报告同样属于数据处理范围；不记录完整令牌、密码或不必要的敏感正文。
- 测试和演示优先使用合成或经确认脱敏的数据；匿名化与可重新关联的假名化不能混为一谈。
- 生产数据进入开发环境、第三方服务或 AI 服务前，必须符合现有授权和数据处理范围；脱敏不自动等于获得对外传输许可。
- 用户删除请求和保留期结束后的清理，应考虑副本、索引、缓存和备份的实际生命周期，说明暂不能即时清除的范围及访问限制。

## 安全验证与问题处理

- 根据改动验证越权、跨租户访问、注入、路径越界和敏感信息泄露等相关失败路径；自动扫描不能代替对业务权限的验证。
- 引入依赖的来源与供应链检查见[依赖与构建](../dependencies/AGENTS.md)，上线时的配置与恢复检查见[运行与发布](../operations/AGENTS.md)。
- 发现安全问题时保存必要且经过脱敏的证据，说明影响范围和已采取措施；不得在公开问题、提交说明或普通日志中复制可用凭据和敏感原始数据。
- 对暂时无法修复的问题，记录实际暴露条件、限制措施及后续处理责任；不得仅以“扫描已忽略”宣称风险消失。
