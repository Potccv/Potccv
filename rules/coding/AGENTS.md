# AGENTS.md — 编程规范

使用本资料编写或修改源码时，遵循本文件及[根目录执行要求](../../AGENTS.md)。维护本目录文档时，同时遵循[通用约定文档的维护要求](../AGENTS.md)。

## 编程基本原则

- 遵循项目已有的代码风格和组织方式，命名清楚，函数与模块职责明确。
- 优先采用满足当前需求的简单实现，避免过度设计。
- 模块通过公开接口协作，保持依赖方向清晰，避免循环依赖；多个模块需要配合时，优先由上层协调。

## 修改范围

- 修改前检查已有改动，保护用户当前工作。
- 只修改当前任务相关内容，不顺带重构或升级无关依赖。

## 子智能体协作

### 启用与参数

- 当前布置的任务量较大时，先向用户询问是否启用子智能体协助编程，并确认同时运行的数量、模型及推理强度；按用户确认的方案调用。同一任务已有明确授权和参数时直接沿用，无须重复确认。
- 询问时以个人配置中的 [`preferences.subagents`](../../profile/AGENTS.md#字段职责) 为默认方案；本次任务中用户明确指定的参数优先。
- 按当前任务中实际同时运行且模型、推理强度均与生效参数完全一致的子智能体计数。不计入主智能体、其他任务的子智能体、空闲或已结束的子智能体，也不计入参数不符或无法核实的子智能体；不能用已创建总数、历史累计调用次数或分批调用总数抵扣并发数量。
- 可以复用此前创建的子智能体，但须先核实其模型和推理强度均与生效参数完全一致，再为其派发当前任务；只有实际开始运行后才计入数量。参数不符或无法核实时，应新建子智能体；新建时显式指定规定的模型和推理强度，不得默认继承主智能体的参数。
- 运行环境的并发上限或模型、推理强度可用性导致无法满足配置时，明确说明要求值、实际值和限制原因，不静默减少数量、替换模型或降低推理强度。

### 调度流程

主智能体统一负责规划、派发、补位和验收。子智能体需要进一步拆分任务时，回报主智能体安排，所有层级共用当前任务的并发名额与参数约束。

1. **先规划依赖。** 明确任务目标、验收标准与先后依赖，维护待执行、运行中、受阻和已完成的工作清单；按配置数量拆出可同时推进的有效分工，优先安排会阻塞后续工作的任务。
2. **明确分工后并行派发。** 每个子任务给出必要上下文、明确目标、输入、修改范围、预期产出和验收要求；划清文件或模块的修改归属，共同修改点由主智能体协调先后顺序。通过复用或新建补齐配置数量，派发后核验实际运行状态、数量和参数。
3. **主智能体同步推进。** 派发后继续处理不依赖子任务结果的关键工作、接口协调或集成准备，避免重复实现已派发的内容；只在下一步确实依赖结果且没有其他有效工作时等待。
4. **随完成随调度。** 任一子智能体交付后，先核验产出，再优先复用它执行下一项依赖已满足的任务，无须等待整批结束。仍有可并行工作时，空闲、结束或失败造成的数量不足须及时补齐；遇到受阻或失败，先查明原因并提供缺失信息、调整分工或接手处理，避免重复派发同一工作。
5. **统一复核与收尾。** 主智能体检查各项结果的证据、接口和结论是否一致，对高风险或相互矛盾的结果安排独立复核，完成集成后按[测试规则](../testing/AGENTS.md#开发与验证)统一验证。工作清单已无可并行任务时进入收尾，不为凑数创建空任务；最终说明实际完成情况、验证结果和遗留问题。

测试时机见[开发与验证](../testing/AGENTS.md#开发与验证)，交付要求见[交付说明](../docs/AGENTS.md#交付说明)。
