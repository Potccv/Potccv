# AGENTS.md — 编程规范

使用本资料编写或修改源码时，遵循本文件及[根目录执行要求](../../AGENTS.md)。维护本目录文档时，同时遵循[通用约定文档的维护要求](../AGENTS.md)。

## 编程基本原则

- 遵循项目已有的代码风格和组织方式，命名清楚，函数与模块职责明确。
- 优先采用满足当前需求的简单实现，避免过度设计。
- 模块通过公开接口协作，保持依赖方向清晰，避免循环依赖；多个模块需要配合时，优先由上层协调。

## 修改范围

- 修改前检查已有改动，保护用户当前工作。
- 只修改当前任务相关内容，不顺带重构或升级无关依赖。

## 子智能体协作

### 启用与参数

- 当前任务存在可独立推进且能节省时间或提高质量的工作时，主动拆分并自动并行调度子智能体；在任务开始、范围或依赖变化时重新评估，不以总体任务量较大或主智能体的推理强度作为启用前提。当前任务授权范围内的分工无须为启用子智能体另行询问；用户明确禁止或限制时遵循其要求。
- 数量、模型和推理强度采用个人配置中的 [`preferences.subagents`](../../profile/AGENTS.md#字段职责)；本次任务中用户明确指定的参数优先。模型和推理强度始终采用生效参数，不随主智能体的推理强度自动改变。
- 有足够独立、有效且依赖已满足的工作时，达到生效配置要求的并发数量；工作不足时按实际有效分工调度，说明要求数量、实际数量及原因，不为凑数强行拆分或创建空任务。后续工作具备并行条件时及时补齐。
- 按当前任务中实际同时运行且模型、推理强度均与生效参数完全一致的子智能体计数。不计入主智能体、其他任务的子智能体、空闲或已结束的子智能体，也不计入参数不符或无法核实的子智能体；不能用已创建总数、历史累计调用次数或分批调用总数抵扣并发数量。
- 运行环境的并发上限或模型、推理强度可用性导致无法满足配置时，明确说明要求值、实际值和限制原因，不静默减少数量、替换模型或降低推理强度。

### 复用与新建

- 每次派发都按任务主题、上下文连续性、已有产出质量和独立性要求选择实例，不固定绑定最初创建的一批子智能体，也不按轮次强制换人。配置数量约束目标并发，不限制任务期间累计创建的实例数量。
- 同一目标下的连续工作、基于已核验产出的修订，已有实例的上下文仍适用且工作正常时可以复用。任务主题、前提或职责明显变化且旧上下文不再适用，或旧结论可能干扰当前判断时，应新建实例；提供当前任务所需的上下文与已核验证据，不将旧推导或未核实结论作为前提。
- 独立复核由未参与原实现或原结论形成的子智能体承担。已有实例满足独立性且上下文适用时可以复用，否则新建；原产出者可以修订自己的工作，但该修订不计为独立复核。
- 补充信息或调整分工后，实例仍重复相同错误、没有有效进展或无法继续运行时，停止向它重复派发，由主智能体接手或改派合适实例，必要时新建。环境故障或输入缺失等共同阻塞须先解决，避免通过反复新建重试同一问题。
- 复用前核实模型和推理强度均与生效参数完全一致；参数不符、无法核实或实例不可用时新建。新建时显式指定生效模型和推理强度，不默认继承主智能体参数。替换仍在运行的实例前，先停止或交接原任务，避免重复执行和修改冲突；派发后按[启用与参数](#启用与参数)核验实际并发数量与环境限制。

### 调度流程

主智能体统一负责规划、派发、补位和验收。子智能体需要进一步拆分任务时，回报主智能体安排，所有层级共用当前任务的并发名额与参数约束。

1. **先规划依赖。** 明确任务目标、验收标准与先后依赖，维护待执行、运行中、受阻和已完成的工作清单；识别可同时推进的有效分工，按[启用与参数](#启用与参数)确定当前并发数量，优先安排会阻塞后续工作的任务。
2. **明确分工后并行派发。** 每个子任务给出必要上下文、明确目标、输入、修改范围、预期产出和验收要求；划清文件或模块的修改归属，共同修改点由主智能体协调先后顺序。按[复用与新建](#复用与新建)选择实例，达到当前确定的并发数量，派发后核验实际运行状态、数量和参数。
3. **主智能体同步推进。** 派发后继续处理不依赖子任务结果的关键工作、接口协调或集成准备，避免重复实现已派发的内容；只在下一步确实依赖结果且没有其他有效工作时等待，优先使用环境提供的等待或通知工具，避免反复查询未变化的状态。
4. **随完成随调度。** 任一子智能体交付后，先核验产出，再为下一项依赖已满足的任务重新选择合适实例，无须等待整批结束。工作清单变化时重新评估并发数量，有足够有效并行工作时，空闲、结束或失败造成的数量不足须及时补齐；遇到受阻或失败，先查明原因，再按[复用与新建](#复用与新建)补充信息、调整分工、接手或替换。
5. **统一复核与收尾。** 主智能体检查各项结果的证据、接口和结论是否一致，对高风险或相互矛盾的结果按[复用与新建](#复用与新建)的独立性要求安排复核，完成集成后按[测试规则](../testing/AGENTS.md#开发与验证)统一验证。工作清单已无可并行任务时进入收尾，不为凑数创建空任务；最终说明实际完成情况、验证结果和遗留问题。

测试时机见[开发与验证](../testing/AGENTS.md#开发与验证)，交付要求见[交付说明](../docs/AGENTS.md#交付说明)。
