# AGENTS.md — 编程规范

使用本资料编写或修改源码时，遵循本文件及[根目录执行要求](../../AGENTS.md)。维护本目录文档时，同时遵循[通用约定文档的维护要求](../AGENTS.md)。

## 编程基本原则

- 遵循项目已有的代码风格和组织方式，命名清楚，函数与模块职责明确。
- 优先采用满足当前需求的简单实现，避免过度设计。
- 模块通过公开接口协作，保持依赖方向清晰，避免循环依赖；多个模块需要配合时，优先由上层协调。

## 修改范围

- 修改前检查已有改动，保护用户当前工作。
- 只修改当前任务相关内容，不顺带重构或升级无关依赖。

## 子智能体协作

- 当前布置的任务量较大时，先向用户询问是否启用子智能体协助编程，并确认同时运行的数量、模型及推理强度；按用户确认的方案调用。同一任务已有明确授权和参数时直接沿用，无须重复确认。
- 询问时以个人配置中的 [`preferences.subagents`](../../profile/AGENTS.md#字段职责) 为默认方案；本次任务中用户明确指定的参数优先。
- 按当前任务中实际同时运行且模型、推理强度均与生效参数完全一致的子智能体计数。不计入主智能体、其他任务的子智能体、空闲或已结束的子智能体，也不计入参数不符或无法核实的子智能体；不能用已创建总数、历史累计调用次数或分批调用总数抵扣并发数量。
- 可以复用此前创建的子智能体，但须先核实其模型和推理强度均与生效参数完全一致，再为其派发当前任务；只有实际开始运行后才计入数量。参数不符或无法核实时，应新建子智能体；新建时显式指定规定的模型和推理强度，不得默认继承主智能体的参数。
- 每轮并行协作开始时，根据生效数量安排可同时执行的分工，通过复用或新建补齐；派发后核验实际运行状态、数量和参数。仍有可并行工作时，发现子智能体空闲、结束或失败导致数量不足，应及时派发后续工作或补齐；进入收尾阶段后不为凑数创建空任务。
- 运行环境的并发上限或模型、推理强度可用性导致无法满足配置时，明确说明要求值、实际值和限制原因，不静默减少数量、替换模型或降低推理强度。
