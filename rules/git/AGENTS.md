# AGENTS.md — 版本与提交

使用本资料组织代码变更、开展评审或处理版本、签名、提交与推送时，遵循本文件及[根目录执行要求](../../AGENTS.md)。维护本目录文档时，同时遵循[通用约定文档的维护要求](../AGENTS.md)。

组织变更或评审时阅读[变更组织](#变更组织)和[代码评审](#代码评审)；版本与提交决策阅读[版本与授权](#版本与授权)。实际提交或推送时再读[提交与核验步骤](#提交与核验步骤)和[补签与推送](#补签与推送)；需要设置或修复签名时再读[签名配置](#签名配置)。

## 变更组织

- 修改前检查当前分支和工作区状态，识别已有改动；不得覆盖、丢弃或一并提交与本次任务无关的用户工作。
- 分支和协作模式沿用项目约定，不强制所有项目采用某种 Git 流程；需要隔离工作时，选择合适的分支或工作区。
- 每项变更围绕一个可说明的目的组织。功能修复、无关重构、全量格式化和大范围依赖升级尽量分开，使差异可以审阅，问题可以定位和恢复。
- 已获准提交时，提交说明解释具体变化和原因，格式遵循项目约定；不能只写“更新”“修复问题”而不说明对象。
- 不无故改写已共享的历史。确需重写、强制推送或解决冲突时，先核对协作影响和已有授权范围；冲突解决后重新检查最终行为，不能仅以冲突标记消失为完成。
- 避免将构建产物、临时数据或个人配置误纳入变更；产物是否需要入库由项目发布策略决定，资料边界见[工作区布局](../workspace/AGENTS.md)。

## 代码评审

- 提交评审前检查最终差异及新增文件，移除无关调试代码、意外格式变化和过时说明；自查对象包括配置、迁移、测试和文档。
- 评审先关注行为是否符合需求，再关注边界条件、兼容性、数据一致性、安全、资源生命周期和验证证据；不能只讨论命名和排版。
- 根据受影响领域引用[编程与设计](../coding/AGENTS.md)、[接口与集成](../interfaces/AGENTS.md)、[数据与存储](../data/AGENTS.md)或[安全与隐私](../security/AGENTS.md)，不在评审流程中另行维护一套重复规则。
- 指出问题时说明触发条件、实际影响和相关位置，区分必须修复的缺陷、改进建议和个人偏好；没有证据时明确不确定性。
- 格式争议优先交给现有工具和项目惯例。能够机械检查的要求逐步自动化，避免把每次人工评审变成重复核对格式。
- 阻断性问题需要修复或形成明确处置依据；存在适用的项目评审与合并要求时，不能绕过要求或代替他人宣称已经批准。

## 变更与交付说明

- PR 或交付说明先描述解决的具体问题及修改后的行为，必要时给出一个触发示例；内容以最终实现为准，不复述无关讨论过程。
- 说明实际验证、兼容影响，以及确有必要的迁移、部署顺序和恢复限制；不要只贴一份没有执行证据的通用检查清单。
- 变更范围调整后同步更新标题和说明；已知缺陷及未执行检查必须如实保留，验证表达遵循[结果与完成标准](../testing/AGENTS.md#结果与完成标准)。

## 版本与授权

- 默认在代码开发完成后，先确认版本号及是否提交，不擅自更改版本或提交代码。
- 项目已有的持续授权及版本约定以项目自身资料为准；历史单次授权不自动推广到未来任务或其他仓库。

## 签名配置

需要设置或修复签名、获取 GitHub 认证参数时，按[个人配置要求](../../profile/AGENTS.md#按任务读取)读取所需字段；已有签名配置满足下表时直接沿用。使用已登记的 SSH 公钥进行签名，Git 配置如下：

| 配置项 | 值或来源 |
|---|---|
| `gpg.format` | `ssh` |
| `user.signingkey` | 本机配置中的 SSH 签名公钥路径 |
| `commit.gpgsign` | `true` |
| `gpg.ssh.allowedSignersFile` | 本机配置中的签名者列表文件路径 |

## 提交与核验步骤

1. 使用 `git diff --cached` 和 `git diff --cached --name-only` 检查暂存内容及文件清单，只纳入应发布内容；个人配置的限制见[凭据与发布要求](../../profile/AGENTS.md#凭据与发布)。
2. 使用 `git commit -S -m "提交说明"` 创建签名提交。
3. 使用 `git verify-commit HEAD` 核验最近一次提交；核验其他提交时将 `HEAD` 替换为对应提交 ID。
4. 推送至 GitHub 后，核对该提交的 `Verified` 状态及 `verification.reason=valid`。

## 补签与推送

`git commit --amend --no-edit -S` 用于补签最近一次提交，会改变提交 ID；使用前确认操作处于当前任务授权范围。

推送远端和分支以项目实际配置为准。SSH remote 不可用时，可使用 HTTPS 与本机凭据。
