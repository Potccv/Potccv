# AGENTS.md — 工作区约定与布局

使用本资料启动项目、准备工作区、生成开发测试文件或参考其他仓库与项目时，遵循本文件及[根目录执行要求](../../AGENTS.md)。维护本目录文档时，同时遵循[通用约定文档的维护要求](../AGENTS.md)。

本目录管理本机工作区的目录、资料、工具、验证运行和任务协作；源码仓库中的代码、正式文档、测试源码及 Git 操作遵循[源码仓库约定](../repo/AGENTS.md)。

| 工作区任务 | 规则入口 |
|---|---|
| 维护本机开发说明、事项进度与验收记录 | [工作区开发文档](docs/AGENTS.md) |
| 开发或运行本机独立辅助工具 | [本机开发工具](tools/AGENTS.md) |
| 执行验证、管理临时批次和保留证据 | [测试执行与验证](testing/AGENTS.md) |
| 派发、复用与验收子智能体任务 | [子智能体协作](collaboration/AGENTS.md) |

## 目录职责

- 使用本约束开始项目前，先在当前工作区内建立与工作区同名的子目录，作为待推送到 GitHub 的项目目录；已有同名目录时沿用。所有计划推送的内容都放入该目录，包括源码、项目文档和必要配置。
- 本机开发资料与待推送的项目目录同级，按下表职责和实际需要创建。默认采用表中名称；已有同职责目录时优先沿用并明确导航，不另建同义目录。不为凑齐结构创建空目录；扩展目录时先明确它与已有目录的职责边界。
- 下表中的目录以工作区根为基准；其中 `<工作区>/docs/` 位于源码仓库之外，不能与 `<源码仓库>/docs/` 混用。文档归属先按[文档位置与适用范围](../AGENTS.md#文档位置与适用范围)判定。

| 可选目录 | 创建条件与用途 |
|---|---|
| `tmp/` | 短期任务文件、一次性脚本和临时打包内容，按任务与批次隔离 |
| `build/` | 可重新生成的编译目录、安装候选和打包暂存；按目标与配置组织，共享依赖、缓存和工具环境按用途分目录 |
| `artifacts/` | 用于交付或需要保留的产物、验收证据和冻结快照，按任务或版本及批次归档 |
| `data/` | 原始素材、数据集和完整采集会话，按主题与来源组织，区分原始和派生数据 |
| `<工作区>/docs/` | 仓库外的本机开发说明、事项进度与验收记录，按[工作区资料存放位置](docs/AGENTS.md#资料存放位置)及[事项管理](docs/AGENTS.md#事项管理)维护 |
| `tools/` | 本机长期复用的辅助工具源码；每个工具位于 `tools/<工具名>/`，独立性与依赖要求见[本机开发工具](tools/AGENTS.md) |
| `refs/` | 需要参考其他仓库或项目的源码时，流程见[参考项目源码](#参考项目源码) |

- 涉及个人配置与凭据时，按[凭据与发布要求](../../profile/AGENTS.md#凭据与发布)单独管理。

## 目录与文件组织

- 创建文件前，先按[目录职责](#目录职责)确定所属项目、工具、主题或任务，优先复用已有合适位置。除导航、配置和必要入口外，不在工作区根或分类目录根散放脚本、日志、编译文件和任务快照。
- 同一任务的一次执行使用同一批次标识；临时文件默认放在 `tmp/<任务>/<批次>/`，测试批次命名见[测试临时目录](testing/AGENTS.md#测试临时目录)。需要跨目录保存的输入、构建与保留产物由任务记录关联，避免复制整套资料来建立关联；完整采集会话按原始数据整体保存。
- 每个本机工具的源码、必要内置资源、配置示例、依赖声明和使用说明归入自己的工具目录；工具生成的环境、缓存、数据和产物仍按[目录职责](#目录职责)存放。运行时共享的依赖按依赖名与版本组织，不放进另一工具的私有目录。
- 稳定源码、数据和文档使用表达用途的名称并持续维护；仅在区分版本或运行批次时增加版本号、日期或时间，不以 `new`、`final-final` 等名称表达有效状态。
- 多份候选、运行副本或历史产物并存时，按[工作区状态记录](docs/AGENTS.md#状态记录)维护唯一当前入口，标明用途、对应版本、路径和实际验证范围；目录存在、序号最大或修改时间最新不代表可用或已验证。

## 操作失败与重试

- 命令或工具报错、超时或取消，不证明未产生副作用或已回滚；先核对目标实际状态，区分未执行、部分完成、已完成但未收到结果和状态未知。
- 停止依赖失败结果的后续步骤，保留已完成的成果，继续不依赖该结果且已获授权的工作。
- 重试前核对不会造成重复提交、重复写入等副作用，并符合工具规则和本次预算；结果未知时先查明状态，连续出现相同错误时先排障，不机械重复。
- 报告失败操作、已知实际状态、尚未确认的内容和安全的下一步；不得仅凭返回码宣称操作已回滚或状态已恢复。

## 生成与清理

- 本次开发与测试生成的临时文件、日志、数据、缓存、构建产物、tarball 和备份均须保存在当前工作区内，禁止放到系统临时目录、工作区外的同级目录或其他位置。任务指定的既有外部输入和已安装依赖可直接引用，不因目录分类搬移或覆盖用户原始资料；参考源码仍按[参考项目源码](#参考项目源码)处理。
- 启动会写文件的工具前，配置本次执行的工作目录、临时目录、输出目录及工具专用缓存或配置目录；临时目录指向对应任务批次，共享缓存单独按用途复用。设置仅作用于所需进程或本机工具配置，不为隔离输出改动用户或机器的全局环境。运行后核对实际生成位置，不能只创建目录而沿用会将文件散落到根目录的默认路径。
- 任务收尾时，将需保留的成果按[目录职责](#目录职责)归档并更新入口，再清理本次产生且已无用途的临时文件；测试清理与失败标记按[测试临时目录](testing/AGENTS.md#测试临时目录)执行。沿用项目的备份和历史保留要求，不将用户文件、完整原始会话、冻结证据或共享依赖当作本次临时文件清理。
- 调整既有布局时，同步核对工具路径配置、文档引用及产物索引；迁移范围限于当前任务，不能仅凭名称、日期或新目录规则擅自搬移或删除其他任务的内容。

## 参考项目源码

- 阅读、检索、分析或比对外部项目源码前，必须先取得本地副本。无论参考项目由用户指定还是智能体自行选择，主智能体及子智能体均须遵循。
- 源码存放于当前工作区的 `refs/<项目名>/`，与待推送的项目目录同级，按需创建。已有对应副本时优先复用，核对来源，并确认或更新到本次所需的分支、标签或提交。
- 复用前核对远端版本；若本地源码已过期，应先拉取对应分支的最新源码并更新本地副本，再开展阅读和分析。用户或任务明确要求固定版本、标签或提交时，以指定版本为准。
- GitHub 等远端平台可用于定位仓库、确认版本、获取源码及查阅 issue、PR 讨论、发布说明等非源码内容；源码内容的检索、阅读、分析与比对必须基于本地文件，不得以网页浏览、远端代码搜索、Raw 链接或文件内容 API 代替本地阅读。
- 可按需使用浅克隆、稀疏检出或源码归档获取所需内容。获取失败时，说明具体原因及对任务的影响，继续处理不依赖该源码的工作，不得自行改用远端源码阅读。
- 派发源码分析任务时，应向子智能体提供已准备好的本地路径及版本信息，并要求其遵循本节的阅读范围与远端访问限制。
- 用户明确要求在线查看源码时，按其指定范围执行例外；仅提供仓库或源码链接不视为在线阅读要求。
