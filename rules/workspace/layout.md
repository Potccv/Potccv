# 工作区布局与文件管理

使用本资料启动项目、准备工作区或生成开发测试文件时，遵循本文件及[工作区入口](AGENTS.md)。维护本文件时，同时遵循[共同写作与核对](../maintenance.md#共同写作与核对)。

本文件管理本机工作区的目录和文件；源码仓库中的代码、正式文档、测试源码及 Git 操作按[源码仓库入口](../repo/AGENTS.md)读取对应规则。

## 目录职责

- 源码仓库放在当前工作区内一个独立的子文件夹中，源码仓库根与工作区根分开；新建仓库按项目名命名，已有独立仓库目录直接沿用。计划推送的源码、项目文档和必要配置放入该目录；调整既有布局时按本文件的迁移要求执行。
- 本机开发资料与待推送的项目目录同级，按下表职责和实际需要创建。默认采用表中名称；已有同职责目录时优先沿用并明确导航，不另建同义目录。不为凑齐结构创建空目录；扩展目录时先明确它与已有目录的职责边界。
- 下表中的目录以工作区根为基准；其中 `<工作区>/docs/` 位于源码仓库之外，不能与 `<源码仓库>/docs/` 混用。文档归属先按[文档位置与适用范围](../scope.md#文档位置与适用范围)判定。

| 可选目录 | 创建条件与用途 |
|---|---|
| `tmp/` | 短期任务文件、一次性脚本和临时打包内容，按任务与批次隔离 |
| `build/` | 可重新生成的编译目录、中间产物、安装候选和打包暂存；按目标、配置和批次组织，共享依赖、缓存和工具环境按用途分目录 |
| `release/` | 会话任务全部完成后生成的完整项目发布包，位于源码仓库之外，版本目录及保留方式见[发布整理与工作区发布目录](../repo/git/release.md#发布整理与工作区发布目录) |
| `data/` | 原始素材、数据集和完整原始采集会话，按主题与来源组织，区分原始和派生数据；会话内的记录与附件一并保留，不按文件扩展名拆散 |
| `<工作区>/docs/` | 仓库外的本机开发说明与事项变化、进度和结果，按[工作区资料存放位置](docs.md#资料存放位置)及[事项管理](tasks/management.md#事项管理)维护，不另建验收报告或证据归档 |
| `tools/` | 本机长期复用的辅助工具源码；每个工具位于 `tools/<工具名>/`，独立性与依赖要求见[本机开发工具](tools.md) |
| `refs/` | 需要参考其他仓库或项目的源码时，流程见[参考项目源码](references.md#参考项目源码) |

- 涉及个人配置与凭据时，按[凭据与发布要求](../../profile/maintenance.md#凭据与发布)单独管理。

## 目录与文件组织

- 创建文件前，先按[目录职责](#目录职责)确定所属项目、工具、主题或任务，优先复用已有合适位置。除导航、配置和必要入口外，不在工作区根或分类目录根散放脚本、日志、编译文件和任务快照。
- 同一任务的一次执行使用同一批次标识；临时文件默认放在 `tmp/<任务>/<批次>/`，测试批次命名见[测试临时目录](testing/execution.md#测试临时目录)。需要跨目录保存的输入、构建与保留产物由任务记录关联，避免复制整套资料来建立关联；完整采集会话按原始数据整体保存。
- 每个本机工具的源码、必要内置资源、配置示例、依赖声明和使用说明归入自己的工具目录；工具生成的环境、缓存、数据和产物仍按[目录职责](#目录职责)存放。运行时共享的依赖按依赖名与版本组织，不放进另一工具的私有目录。
- 稳定源码、数据和文档使用表达用途的名称并持续维护；仅在区分版本或运行批次时增加版本号、日期或时间，不以 `new`、`final-final` 等名称表达有效状态。
- 多份候选、运行副本或历史产物并存时，按[工作区状态记录](docs.md#状态记录)维护唯一当前入口，标明用途、对应版本、路径和实际验证范围；目录存在、序号最大或修改时间最新不代表可用或已验证。

## 生成与清理

- 本次开发与测试生成的临时文件、日志、数据、缓存、构建产物、tarball 和备份均须保存在当前工作区内，禁止放到系统临时目录、工作区外的同级目录或其他位置。任务指定的既有外部输入和已安装依赖可直接引用，不因目录分类搬移或覆盖用户原始资料；参考源码仍按[参考项目源码](references.md#参考项目源码)处理。
- 启动会写文件的工具前，配置本次执行的工作目录、临时目录、输出目录及工具专用缓存或配置目录；临时目录指向对应任务批次，共享缓存单独按用途复用。设置仅作用于所需进程或本机工具配置，不为隔离输出改动用户或机器的全局环境。运行后核对实际生成位置，不能只创建目录而沿用会将文件散落到根目录的默认路径。
- 任务收尾时，将需要交付的成果按[目录职责](#目录职责)保存在对应位置，发布包放入工作区 `release/`；事项只更新原文件，不为留证另建报告或归档副本。再清理本次产生且已无用途的临时文件；测试清理及删除受阻后的 `.trash` 处理按[测试临时目录](testing/execution.md#测试临时目录)执行。工作区根 `.trash/` 仅按需保存清理受阻的完整目录，或经授权布局迁移暂存的旧目录，不纳入普通扫描或自动清理。沿用项目的备份和历史保留要求，不将用户文件、完整原始会话、已有冻结证据或共享依赖当作本次临时文件清理。
- 调整既有布局时，同步核对工具路径配置、文档引用及产物索引；迁移范围限于当前任务，不能仅凭名称、日期或新目录规则擅自搬移或删除其他任务的内容。
