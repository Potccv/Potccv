# 参考项目源码

阅读、检索、分析或比对外部项目源码时，遵循本文件及[工作区入口](AGENTS.md)；本地副本的位置同时遵循[工作区布局](layout.md)。

## 参考项目源码

- 阅读、检索、分析或比对外部项目源码前，必须先取得本地副本。无论参考项目由用户指定还是智能体自行选择，主智能体及子智能体均须遵循。
- 每个参考项目默认只维护一份本地源码，存放于当前工作区的 `refs/<项目名>/`，与待推送的项目目录同级，按需创建。已有对应副本时，核对来源后直接复用，不因子任务、日期或提交号另建副本。
- 默认跟随远端默认分支的最新提交；用户明确指定其他分支时，跟随该分支的最新提交。不自行选择旧版本、标签或提交作为固定目标；只有用户明确要求固定版本、标签或提交时，才按其指定执行。
- 每次任务首次使用该参考项目时，由主智能体统一核对远端分支；本地落后时在同一副本中增量同步，已是最新时直接复用。同步完成后，同一任务的后续阅读和子任务复用该结果，不各自重复克隆、fetch 或 pull。新任务再次使用、用户明确要求刷新，或获知所跟随分支已有新提交时，由主智能体统一同步。
- 实际提交号仅用于记录分析依据，不作为后续任务或子智能体锁定、回退源码的目标。更新参考源码前，由主智能体协调正在使用该副本的分析任务，更新后统一使用新版本，不让各协作者在同一副本中来回切换提交。
- GitHub 等远端平台可用于定位仓库、确认版本、获取源码及查阅 issue、PR 讨论、发布说明等非源码内容；源码内容的检索、阅读、分析与比对必须基于本地文件，不得以网页浏览、远端代码搜索、Raw 链接或文件内容 API 代替本地阅读。
- 可按需使用浅克隆、稀疏检出或源码归档获取所需内容。获取失败时，说明具体原因及对任务的影响，继续处理不依赖该源码的工作，不得自行改用远端源码阅读。
- 派发源码分析任务时，应向子智能体提供已准备好的本地路径、跟随的远端分支和同步结果；提交号只作来源记录。子智能体直接读取该副本，需要更新时交由主智能体统一处理，并遵循本节的阅读范围与远端访问限制。
- 用户明确要求在线查看源码时，按其指定范围执行例外；仅提供仓库或源码链接不视为在线阅读要求。
