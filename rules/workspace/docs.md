# 工作区开发文档

先按[文档位置与适用范围](../scope.md#文档位置与适用范围)确认目标。本文件仅适用于 `<工作区>/docs/`：它位于所有源码仓库之外，与项目目录同级，用于本机开发说明、事项进度与必要验证结果。下文中的路径均以已确认的工作区为基准，不按当前工作目录推断；这些事项与时间规则不适用于 `<源码仓库>/docs/`。

共同写作和验证要求见[共同写作与核对](../maintenance.md#共同写作与核对)。源码契约、项目架构与正式使用说明按[源码仓库文档](../repo/docs.md)维护；本机资料通过链接引用正式说明，不复制维护项目事实。

## 写作与维护

- 本机现行说明在固定主题文件内原位覆盖更新；用法变化时同步改写正文和示例，不另建日期版、最新版或副本并行维护同一用法。
- 更新后检查旧说明和副本；已过期且被新说明完整替代的文件，在确认仍有效的内容、未关闭事项和授权限制已保留后清除，并同步更新导航和引用。不仅凭日期较早就判为过期。

## 资料存放位置

目录分类及构建输出、临时文件、原始数据、工具源码、个人配置与凭据的位置遵循[目录职责](layout.md#目录职责)；已有同职责目录优先沿用，不为统一名称自行全量迁移。

本机方案、任务操作与协作记录、私有运维资料、使用版本、任务进展、部署与文字验证结论、事项、持续授权与限制、交付历史放在 `<工作区>/docs/`，按项目或用途分类；持续跟踪的事项按[状态记录](#状态记录)维护，敏感资料不写入公开项目文档。本机资料引用工具自身的用途和操作说明。

需要从个人配置查找资料路径时，见[个人配置字段](../../profile/fields.md#字段职责)。`<工作区>/docs/` 不作为安装包、SDK、工具源码、构建输出或发布包的堆放位置；保留成果的位置见[生成与清理](layout.md#生成与清理)，发布包的交付要求见[版本、发布与交付](../repo/git/release.md)。不要求每个临时文件配备 README。Potccv 约束仓库不集中收纳其他项目的本机资料。

## 状态记录

- 需要交接或持续跟踪的任务按[事项管理](tasks/management.md#事项管理)，在 `<工作区>/docs/tasks/todo/`、`doing/`、`done/`、`drop/` 中维护唯一事项文件；已有事项原位更新，在“当前进展与接续”中简短写明实际变化、结果、必要验证及未完成项，并保留仍有效的授权和限制。README、概览和跨事项主题入口只提供导航与关联，不重复维护单个事项的进度。
- 一次性且无事项的任务在回复中说明结果即可，不为留证建项；不另建证据文件、证据包、归档副本或额外验收报告，测试通过、发布或交付本身也不触发这些文件的创建。
- 记录源码、部署或验收状态时，注明实际核验时间和范围；搬移文档不更新实测日期。章节排序、版本号和源码推送均不构成实际部署结果的证据。历史记录保留当时的事实、日期和限制，不为采用当前记录方式删除用户历史文件。
