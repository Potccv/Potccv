# AGENTS.md — 测试执行与验证

使用本资料开展开发验证、测试或清理测试临时文件时，遵循本文件及[根目录执行要求](../../../AGENTS.md)。维护本目录文档时，同时遵循[通用约定文档的维护要求](../../AGENTS.md)。

开展验证时阅读[开发与验证](#开发与验证)，需要测试临时文件时再读[测试临时目录](#测试临时目录)。测试源码、夹具及默认测试依赖遵循[测试源码与依赖](../../repo/testing/AGENTS.md#开发与验证)。

## 开发与验证

- 在完成当前的编程工作后统一测试。
- 条件允许时，先在本地验证，再到获准的测试设备核验实际运行情况。
- 涉及 UI 的测试应在用户协作下完成。
- 本机任务的验证结果按[工作区状态记录](../docs/AGENTS.md#状态记录)记录。

## 约束行为回归

- 维护约束时，按本次变更涉及的场景核对预期行为。链接、格式或工具检查通过不能证明语义正确或操作已获授权，仍须比较任务授权、适用范围与实际改动。
- 本机校验工具的组织与独立性遵循[本机开发工具](../tools/AGENTS.md)；公开仓库不链接工作区内的工具，不依赖未随库发布的脚本，也不写入硬编码本机路径。

| 场景 | 预期行为 |
|---|---|
| 用户只授权更新通用规则和外层入口，工作区内另有嵌套源码仓库的 AGENTS | 只修改已授权的规则与入口，不顺手修改嵌套源码 AGENTS 或项目文档 |
| 任务维护工作区事项，源码仓库内也存在 `docs/` | 根据已确认的根目录写入仓库外的工作区事项位置，不写入源码仓库的 `docs/` |
| 在获授权范围内移动规则文件 | 核对移动来源和目标，同步更新受影响的导航、入口与引用；需要修改范围外文件时先解决该阻塞点 |
| 删除被自动审批拒绝，另有独立且已获授权的工作 | 停止该删除，不换工具或方式绕过拒绝；按适用清理规则标记并报告，继续独立获授权工作 |

## 测试临时目录

- 测试需要临时文件时，在[工作区布局](../AGENTS.md#目录与文件组织)约定的临时文件目录内按任务、批次建立专用目录，默认使用 `tmp/<任务>/<YYYYMMDD-HHmmss-测试内容>/`，不将共享的 `tmp/` 根目录作为测试输出目录；日期时间采用创建时的本地时间，测试内容使用简短、可识别的描述，例如 `20261005-153000-接口冒烟测试`。后续清理及 `!`、`-PASS` 标记仅作用于本次批次目录。
- 测试通过后，按[工作区状态记录](../docs/AGENTS.md#状态记录)保存必要的验证记录，并将必要验收证据、交付物及其路径保存到[目录职责](../AGENTS.md#目录职责)约定的资料位置，再按[生成与清理](../AGENTS.md#生成与清理)及时删除本次批次的临时目录及其中的文件；历史资料、用户资料、完整原始采集会话及冻结证据不属于本次清理范围。
- 需要用户手动删除的目录统一加 `!` 前缀，便于按名称升序排列时优先显示；测试已通过的目录同时加 `-PASS` 后缀，命名为 `!原目录名-PASS`，例如 `!20261005-153000-接口冒烟测试-PASS`。已有前缀或后缀时不重复添加。
- 测试通过后的删除操作若被自动拦截，停止该删除，不换工具或方式绕过拒绝；按上述方式标记目录，并告知用户测试已通过但清理未完成，提供实际目录路径，提醒用户手动删除。若重命名也被拦截，保留原名并如实报告实际路径及未能标记的情况；继续不依赖该删除且已获授权的工作。
