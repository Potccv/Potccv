# 测试执行与临时目录

使用本资料开展开发验证、测试或清理测试临时文件时，遵循本文件及[测试入口](AGENTS.md)。维护本目录文档时，同时遵循[规则维护入口](../../AGENTS.md#维护规则)。

开展验证时阅读[开发与验证](#开发与验证)，需要测试临时文件时再读[测试临时目录](#测试临时目录)。测试源码、夹具及默认测试依赖遵循[测试源码与依赖](../../repo/testing.md#开发与验证)。

## 开发与验证

- 在完成当前的编程工作后统一测试。
- 条件允许时，先在本地验证，再到获准的测试设备核验实际运行情况。
- 涉及 UI 的测试应在用户协作下完成。
- 本机任务的验证结果按[工作区状态记录](../docs.md#状态记录)记录。

## 测试临时目录

- 测试需要临时文件时，在[工作区布局](../layout.md#目录与文件组织)约定的临时文件目录内按任务、批次建立专用目录，默认使用 `tmp/<任务>/<YYYYMMDD-HHmmss-测试内容>/`，不将共享的 `tmp/` 根目录作为测试输出目录；日期时间采用创建时的本地时间，测试内容使用简短、可识别的描述，例如 `20261005-153000-接口冒烟测试`。
- 测试通过后，把实际执行的检查与结果记录在对应事项的“当前进展与接续”或必要的验证记录中，默认不归档验收证据；只有交付、发布、用户明确要求或需要保留交付物时，才将必要证据保存到[目录职责](../layout.md#目录职责)约定的资料位置。随后按[生成与清理](../layout.md#生成与清理)及时删除本次批次的临时目录及其中的文件；历史资料、用户资料、完整原始采集会话及冻结证据不属于本次清理范围。
- 清理 `build/`、`releases/` 或 `tmp/` 批次目录的删除操作若被自动拦截，停止该删除，不换工具或方式绕过；按需创建工作区根 `<工作区>/.trash/`，将完整目录移入其中并报告实际路径，不为目录添加前缀、后缀或其他标记。`.trash` 只保存清理受阻的残留目录，不纳入普通扫描或自动清理；移动也被拦截时保留原路径并如实报告，继续不依赖该删除且已获授权的工作。

维护约束时，按[约束行为回归](regressions.md#约束行为回归)选择与本次变更相关的最小案例。
