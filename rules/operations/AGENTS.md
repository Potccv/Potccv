# AGENTS.md — 运行与发布

使用本资料调整运行配置、日志、性能、可靠性或执行发布与恢复时，遵循本文件及[根目录执行要求](../../AGENTS.md)。维护本目录文档时，同时遵循[通用约定文档的维护要求](../AGENTS.md)。

运行相关改动先掌握[配置与启动](#配置与启动)，其余章节按实际任务选读。以下服务运行条目仅适用于存在相应服务或部署流程的项目，不要求本地脚本建设完整运维平台。

## 配置与启动

- 将环境差异放在明确的配置边界，说明来源、优先级、默认值、必填项和修改后何时生效；避免同一配置散落在多处互相覆盖。
- 启动时验证关键配置的类型、范围及组合关系。必要配置缺失时给出可定位错误，不能静默连接错误环境或使用不安全的默认值。
- 区分开发、测试与生产环境的地址、凭据和资源，启动及部署记录应能确定实际目标；不得仅凭目录名推断运行环境。
- 热更新需要定义原子性、校验失败后的行为和在途请求语义；不支持安全热更新时，明确要求重启。
- 功能开关注明用途、默认状态和移除条件；涉及数据格式或持久化变化时，关闭开关不等于完成回退。

## 日志指标与追踪

- 日志记录有助于解释行为的事件和上下文，沿用项目统一结构；按需包含时间、级别、组件、业务操作和关联标识。
- 区分调试信息、正常事件、可恢复异常和需要处理的故障。避免逐层记录同一异常造成重复噪声，也不能吞掉最终无人处理的错误。
- 关联标识应可用于连接请求、异步任务与外部调用；不把它同时当作访问凭据。
- 日志及遥测中的敏感数据处理遵循[隐私与数据使用](../security/AGENTS.md#隐私与数据使用)，外部输入进入日志时应防止伪造换行或破坏结构。
- 服务按实际需要观察请求量、错误率、延迟分布和资源饱和度；异步系统还关注队列积压、处理延迟及失败消息。
- 选择能反映用户体验的分位延迟和错误指标，不能仅凭平均耗时证明高峰表现正常。
- 指标标签保持可控基数，不直接使用无限增长的用户 ID、订单 ID 或原始 URL；详细定位信息放在适当的日志或追踪中。
- 告警应对应可采取的动作，明确阈值、观察窗口和处理责任；控制重复告警，避免把每一条普通错误日志都变成通知。

## 健康检查与资源边界

- 区分进程存活、是否准备接收流量和关键功能是否可用；健康检查应轻量且有界。
- 存活检查不应因短暂的下游故障引发全体实例反复重启；就绪检查根据服务实际依赖和降级能力决定是否接受新流量。
- 为连接、线程、文件句柄、队列、内存、磁盘及后台任务设置合理边界，并处理达到边界后的拒绝、等待或降级行为。
- 使用有限队列和必要的背压，避免在过载时无限缓存请求；限流应有明确作用范围和可识别的返回结果。
- 外部调用的超时、重试和幂等遵循[接口与集成](../interfaces/AGENTS.md#超时重试与幂等)；熔断、隔离和降级仅在实际故障模式需要时引入。
- 停止服务时按需要先停止接收新任务，再在有界时间内完成或安全取消在途工作，释放资源并保存必要进度。
- 降级结果必须符合业务允许的语义，不得把丢单、越权或账务错误包装为服务可用。

## 性能工程

- 先基于真实负载建立基线和目标，再定位瓶颈；优化算法、数据访问和资源使用前，避免仅凭直觉微调代码。
- 测量时记录环境、数据量、并发、缓存状态和样本条件，关注吞吐、延迟分布、错误率和资源成本。
- 优先检查不必要的重复计算、数据库往返、序列化、大对象复制和阻塞；不默认更复杂的并发一定更快。
- 优化后在可比条件下验证收益和正确性，不牺牲权限检查、精度或必要的持久性来制造更好指标。
- 昂贵的缓存、预计算或专门基础设施应有测量依据及维护成本评估；没有性能问题时保持实现清楚。

## 发布与回退

1. 核对本次已有授权、目标环境、源码版本及待发布产物；版本与提交按[版本与授权](../git/AGENTS.md#版本与授权)执行，不能将构建成功当作已经部署。
2. 完成与风险匹配的发布前检查，确认配置、依赖、权限、容量和兼容性；验证证据按[测试与验证](../testing/AGENTS.md#结果与完成标准)记录。
3. 涉及数据变化时，先落实[数据迁移](../data/AGENTS.md#数据迁移)要求，明确新旧实例共存、迁移执行和清理旧结构的先后顺序。
4. 优先推广同一已验证产物，保留产物标识和配置版本；重新构建会产生需要重新核验的交付对象。
5. 根据影响范围采用一次发布、分批、灰度或其他项目已有方式；发布前明确失败判定、停止条件和恢复操作，不把灰度发布当成所有项目的强制架构。
6. 发布后核验实际版本、关键功能、错误率及必要的数据状态，记录核验时间和范围；只看到进程启动不能证明业务验收通过。
7. 需要回退时，确认旧版本能读取当前数据与配置，并处理消息、任务和其他外部副作用；无法安全回退时执行预先准备的前向修复或恢复方案。
8. 保存必要的发布证据和未关闭事项，按[状态记录](../docs/AGENTS.md#状态记录)区分源码、部署和验收状态。

## 故障与恢复

- 优先控制用户影响并保护数据，保留关键日志、版本、配置和发生时间；根因未确认时说明证据边界，避免过早下结论。
- 恢复手段可以是回退、限流、禁用故障功能、修复配置或恢复数据，选择与实际故障及授权范围匹配的动作。
- 对有持续运行要求的系统，按业务需要明确恢复时间目标和允许的数据损失，并通过恢复演练检验备份、权限和操作步骤。
- 故障处理结束后验证用户路径和数据一致性，不以告警消失作为唯一恢复标准。
- 重大或重复故障记录影响、时间线、原因、检测与恢复不足，以及可落实的改进；记录位置遵循[文档职责](../docs/AGENTS.md#文档职责)。
