# 版本、发布与交付

使用本资料处理发布产物的构建、交付、版本、签名、提交或推送时，遵循本文件及[版本、发布与提交入口](AGENTS.md)。维护本目录文档时，同时遵循[共同写作与核对](../../maintenance.md#共同写作与核对)。

本约定中的 demo 与 release 统一指项目发布产物，按同一套规则构建和交付。

## 构建与交付

生成发布产物时，遵循[项目构建](../../workspace/build.md)；涉及测试源码时阅读[源码测试与验证](../testing.md)，开展运行验证时阅读[工作区测试与验证](../../workspace/testing/execution.md)。

- 默认构建整个项目，交付完整项目编译后的产物；只有用户明确指定仅包含哪些功能时，才按其指定范围生成产物。
- 按项目已有打包要求生成完整发布包，不额外强制生成校验和、发布说明或证据归档文件。产物存放按[发布整理与工作区发布目录](#发布整理与工作区发布目录)处理；交付回复说明产物路径、运行方式及实际验证结果。

## 版本与授权

- 按[个人配置的按任务读取要求](../../../profile/AGENTS.md#按任务读取)读取 `preferences.release.create_after_change`：为 `true` 时，在本会话截至收尾时已布置的任务全部完成且适用验证通过后，对本次修改的项目统一打包一次；子任务、单个文件或阶段完成不触发，也不等待未来尚未布置的任务。为 `false` 时关闭自动打包。打包前按[发布整理与工作区发布目录](#发布整理与工作区发布目录)确认版本号和可发布构建。
- 先按[个人配置的按任务读取要求](../../../profile/AGENTS.md#按任务读取)选取配置并按需读取，再按[字段职责](../../../profile/fields.md#字段职责)读取 `preferences.auto_commit_and_push`：为 `false` 时不自动提交或推送；为 `true` 时，在必要验证通过后按[提交与核验步骤](commits.md#提交与核验步骤)创建签名提交并推送至 GitHub，无须每次重复确认。该项只控制源码提交及其常规推送，不能授权 release 推送。
- release 推送包括发布包上传、发布标签、GitHub Release 发布等操作。只有用户明确要求推送 release，或按[个人配置](../../../profile/AGENTS.md#按任务读取)读取到 `preferences.release.auto_push=true` 时才执行；不能因 `preferences.auto_commit_and_push=true` 自动推送 release。没有上述授权时，保留已生成的本地 release，并报告未推送。发布包位于源码仓库外，不夹入源码提交。
- 用户明确要求每次修改源码后提交时，将当前生效配置中的该项改为 `true`；用户要求停止自动提交时改为 `false`。单次提交或推送请求只执行当次操作，不改变此配置。
- 版本号遵循用户要求与项目既有约定，不擅自更改。
- 项目已有的持续授权及版本约定以项目自身资料为准；历史单次授权不自动推广到未来任务或其他仓库。

## 发布整理与工作区发布目录

- 完整发布包放在源码仓库外的 `<工作区>/release/<版本>/`，目录名使用单数 `release`。仅在已确认已有版本号和可发布构建存在时按需创建目录，不预建空 release；构建中间产物、缓存和安装候选留在 `build/` 等构建目录，不复制进版本目录。
- 没有已有版本号或可发布构建时，如实报告无法生成 release 的原因，不编造版本号、构建产物或创建空 release。
- 完成新发布包后，仅保留最近三个版本，并清理更早的发布包。按项目已经声明的版本规则及其预发布优先级确定新旧顺序，不用目录修改时间或未经定义的字符串排序代替。本条已授权清理 `<工作区>/release/` 内更早的发布包，无须每次另行确认；授权不扩展到源码、Git 提交、标签或其他历史。
- 删除或清理 `<工作区>/release/` 中的版本目录，或因构建失败需要清理完整发布目录时，删除被拒绝或失败就停止该删除，不改用其他工具或方式绕过；将待清理的完整目录移入 `<工作区>/.trash/`（按需创建，可在其下保留原发布路径和批次标识），并报告实际路径。移动也失败时保留原目录并如实报告。
