# AGENTS.md — 版本、发布与提交

使用本资料处理版本、签名、提交或推送时，遵循本文件及[根目录执行要求](../../../AGENTS.md)。维护本目录文档时，同时遵循[源码仓库约定的维护要求](../AGENTS.md)。

版本、发布与提交决策阅读[版本与授权](#版本与授权)及[发布整理与源码仓库发布目录](#发布整理与源码仓库发布目录)；实际提交或推送时再读[提交与核验步骤](#提交与核验步骤)和[补签与推送](#补签与推送)；需要设置或修复签名时再读[签名配置](#签名配置)。

## 版本与授权

- 每次源码修改完成进入收尾时，默认开启并要求执行一次新的 release 生成或整理；先按[发布整理与源码仓库发布目录](#发布整理与源码仓库发布目录)确认能否形成有效版本，再按本节决定提交和推送。
- 按[个人配置](../../../profile/AGENTS.md#选择配置)读取 [`preferences.auto_commit_and_push`](../../../profile/AGENTS.md#字段职责)：为 `false` 时不自动提交或推送；为 `true` 时，在必要验证通过后按[提交与核验步骤](#提交与核验步骤)创建签名提交并推送至 GitHub，无须每次重复确认。该项只控制源码提交及其常规推送，不能授权 release 推送。
- release 推送必须有本轮用户明确授权，或按[个人配置](../../../profile/AGENTS.md#按任务读取)读取到独立的 release 推送偏好且明确允许；不能因 `preferences.auto_commit_and_push=true` 自动推送 release。没有上述授权时，保留已生成的本地 release，并报告未推送。
- 用户明确要求每次修改源码后提交时，将当前生效配置中的该项改为 `true`；用户要求停止自动提交时改为 `false`。单次提交或推送请求只执行当次操作，不改变此配置。
- 版本号遵循用户要求与项目既有约定，不擅自更改。
- 项目已有的持续授权及版本约定以项目自身资料为准；历史单次授权不自动推广到未来任务或其他仓库。

## 发布整理与源码仓库发布目录

- 每次修改完成收尾时都要尝试生成或整理新的 release；仅在已确认版本号和可发布构建存在时，在源码仓库根目录按需创建 `releases/` 及 `releases/<版本>/`，不得预建空目录，也不在 `.gitignore` 中忽略它。每个版本目录内必须同时包含完整的用户发布包、对应校验和文件和发布说明；构建中间产物、缓存和安装候选留在 `build/` 等构建目录，不复制进版本目录。
- 没有版本号或可发布构建时，报告无法生成 release 的限制，不能伪造版本号、伪造构建产物或创建空 release；该次收尾仍须记录 release 未生成的原因。
- 发布后按项目已经声明的版本规则确定新旧顺序：遵循项目采用的版本规范及其预发布优先级，不能用目录修改时间或未经定义的字符串排序代替。常规保留最近三个版本；准备清理更旧版本前，先检查仓库文档、脚本、配置、任务记录及外部交付说明中的引用，并确认本次删除已有明确授权。仍被引用或未获授权的版本不得清理，应报告阻塞原因。
- 删除或清理 `releases/` 中的版本目录，或因构建失败需要清理完整发布目录时，删除被拒绝或失败就停止该删除，不改用其他工具或方式绕过；将待清理的完整目录移入已定义的工作区根 `<workspace>/.trash/`（即源码仓库父级的 `<工作区>`，按需创建，可在其下保留原发布路径和批次标识），并报告实际路径。移动也失败时保留原目录并如实报告。
- 工作区只保留最近三个版本不会删除 Git 提交、标签或其他历史；需要分发大包时可使用 GitHub Releases 资产，但仍须遵循用户对源码仓库 `releases/` 目录和发布内容的明确意图，不以远端资产替代未经授权的本地发布目录变更。

## 签名配置

需要设置或修复签名、获取 GitHub 认证参数时，按[个人配置要求](../../../profile/AGENTS.md#按任务读取)读取所需字段；已有签名配置满足下表时直接沿用。使用已登记的 SSH 公钥进行签名，Git 配置如下：

| 配置项 | 值或来源 |
|---|---|
| `gpg.format` | `ssh` |
| `user.signingkey` | 本机配置中的 SSH 签名公钥路径 |
| `commit.gpgsign` | `true` |
| `gpg.ssh.allowedSignersFile` | 本机配置中的签名者列表文件路径 |

## 提交与核验步骤

1. 使用 `git diff --cached` 和 `git diff --cached --name-only` 检查暂存内容及文件清单，只纳入应发布内容；个人配置的限制见[凭据与发布要求](../../../profile/AGENTS.md#凭据与发布)。
2. 使用 `git commit -S -m "提交说明"` 创建签名提交。
3. 使用 `git verify-commit HEAD` 核验最近一次提交；核验其他提交时将 `HEAD` 替换为对应提交 ID。
4. 推送至 GitHub 后，核对该提交的 `Verified` 状态及 `verification.reason=valid`。

## 补签与推送

`git commit --amend --no-edit -S` 用于补签最近一次提交，会改变提交 ID；使用前确认操作处于当前任务授权范围。

推送远端和分支以项目实际配置为准。SSH remote 不可用时，可使用 HTTPS 与本机凭据。
