# 约束范围与任务边界

本文件补充[根目录执行要求](../AGENTS.md)，按作用范围选择源码仓库或工作区规则，维护规则时另见[共同写作与核对](maintenance.md#共同写作与核对)。

## 规则归属

按[通用规则入口的作用范围](AGENTS.md#按作用范围读取)选择源码仓库或工作区规则。具体执行规则只在所属目录维护；跨范围的任务分别读取所需规则，不因目录分类而扩大操作授权。

## 任务范围与冲突处理

- 动手前确认工作区根、源码仓库根，以及任务允许写入的完整路径或目录范围；范围包括直接编辑、命令生成的输出、移动的来源与目标和删除对象。根据已有授权确定范围，只有缺失信息阻塞操作时才询问用户。
- 执行中和收尾时，将实际改动与授权范围比较；区分本次改动与已有或其他协作者的改动，发现越界时停止相关操作并处理偏差。更新通用约束不自动授权修改采用约束的项目文档。
- 约定冲突时先判定各自适用范围，再在平台约束内遵循本轮明确用户指令及仍有效的持续授权；项目专用约定只在其所属范围内生效。
- 同一范围内仍有会影响结果或造成越界风险的矛盾时，只针对阻塞点询问用户；已有授权足以决定的操作继续执行，无需反复确认。

## 文档位置与适用范围

- 先确认当前任务的工作区根、源码仓库根和目标文件的完整路径。源码仓库通常位于工作区内，因此先判断文件是否属于源码仓库；不能仅凭目录名 `docs`、当前工作目录或文件是否被 Git 忽略来确定归属。
- 本文中的 `<工作区>` 与 `<源码仓库>` 表示已确认的实际根目录，不是相对路径的简写；两者内部的 `docs/` 是不同的维护范围。

| 目标位置 | 用途与执行规则 |
|---|---|
| `<工作区>/docs/`，位于源码仓库之外 | 本机开发说明、事项进度与验收记录，遵循[工作区开发文档](workspace/docs.md) |
| `<源码仓库>/docs/`，以及仓库内的 README、模块说明、CONTRIBUTING 和 AGENTS | 随源码维护的项目说明、接口与使用文档，遵循[源码仓库文档](repo/docs.md) |

- 工作区事项的状态目录、文末时间、原位覆盖与过期旧文件清理规则仅在其规定的工作区范围内执行，不自动套用到源码仓库文档。
- 维护一类文档不自动扩展到另一类，不因同名目录而跨范围创建、移动或删除文件。

## 交付说明

- 简要说明修改的是工作区文档还是源码仓库文档，并报告实际改动、验证结果和遗留问题。
