# AGENTS.md — 数据与存储

使用本资料设计数据模型、修改持久化逻辑、使用缓存或执行数据迁移时，遵循本文件及[根目录执行要求](../../AGENTS.md)。维护本目录文档时，同时遵循[通用约定文档的维护要求](../AGENTS.md)。

先掌握[模型与约束](#模型与约束)和[数据表示](#数据表示)；事务、查询、迁移、缓存和文件存储按实际涉及范围选读。

## 模型与约束

- 为关键数据定义含义、来源、所有者、生命周期和唯一标识；同一数据的权威来源应明确，派生值注明生成和更新方式。
- 根据真实访问方式和一致性需求选择存储，不默认所有数据都需要关系库、文档库、搜索引擎或多份副本。
- 将必须始终成立的不变量落实到存储层可提供的约束，例如唯一、非空、外键和检查约束；应用层预检查用于改善体验，不能替代并发条件下的最终约束。
- 存储无法直接保证某项约束时，明确替代机制、竞态风险和修复办法，不靠约定假装已经保证。
- 区分业务标识、存储主键和外部展示标识；避免让内部自增 ID 同时承担安全授权作用。
- 删除、软删除、级联删除和数据归档各有明确语义；采用软删除时同时处理唯一性、查询过滤、恢复和最终清理。

## 数据表示

- 明确字符编码和文本比较规则；规范化处理不能无意改变密码、签名原文或其他要求保留精确字节的数据。
- 金额和精度按[类型与边界值](../coding/AGENTS.md#类型与边界值)处理；存储、接口和计算链路使用一致的单位和舍入规则。
- 表示绝对时间点时优先使用 UTC 存储并在展示时转换；生日、营业日期等当地日期不强行转换为 UTC 时间点。
- 涉及“每天当地 09:00”这类计划时，保存足够的时区及日历语义，并定义夏令时造成的重复或不存在时间如何处理。
- 持续时长明确单位；测量耗时优先使用单调时钟，不能假定系统墙上时钟永远向前。
- 对需要长期保留或跨版本传输的数据，明确序列化格式、版本和演进方式；不能直接持久化不稳定的内部对象布局。

## 事务与并发一致性

- 以业务不变量确定事务边界；需要同时成功的数据库操作置于适当事务中，避免半写入状态。
- 明确数据库隔离级别和它实际提供的保证；对丢失更新、重复插入或库存超卖，按场景使用原子更新、唯一约束、乐观版本或锁。
- 事务保持必要且短小，避免在持有数据库锁时等待用户操作或长时间调用外部服务。
- 重试事务前确认其副作用能够安全重复；被事务回滚的数据库写入，不会自动撤回已发送的邮件或已完成的外部付款。
- 跨数据库、缓存、消息系统和外部服务的流程需要明确一致性目标。可按需求使用事务发件箱、对账或补偿，不宣称普通本地事务能覆盖所有系统。
- 补偿属于新的业务操作，应处理自身失败；只有业务允许时才使用最终一致性，并明确可接受延迟和恢复路径。

## 查询与容量

- 使用参数化查询或正确绑定参数的数据库接口；动态字段名、排序表达式等不能绑定的部分必须通过允许清单控制。
- 根据真实查询建立索引，关注选择性、联合索引顺序、写入成本和空间占用；重要慢查询通过执行计划和测量定位。
- 避免无界查询、逐项重复查询和一次加载全部数据。分页、批量读取或流式处理应与数据规模和一致性需求匹配。
- 为连接池、查询时长和批量写入设置合理边界，关注连接耗尽、锁等待及失败后的回收。
- 容量评估包含数据增长、索引、日志、保留期和峰值负载，不只看开发环境的小样本表现。

## 数据迁移

1. 明确目标环境、受影响对象、数据量、锁表或停机风险、应用版本兼容范围，以及执行该迁移所需的现有授权。
2. 将结构迁移和必要的数据迁移纳入版本管理，定义执行顺序、完成标记和中断恢复方式；已被共享环境执行的迁移不要直接改写，使用新的修正迁移。
3. 持续运行的系统优先采用兼容扩展、回填、切换、观察、收缩的分阶段方式；未完成旧客户端和旧实例切换前，不提前删除旧字段。
4. 大量回填采用可控批次、进度记录、速率限制和可安全恢复的设计，避免长事务及无界资源占用。
5. 按风险在代表性数据或隔离环境中演练，校验记录数量、关键业务约束、默认值和必要的校验和；迁移命令返回成功不代表业务数据一定正确。
6. 对破坏性迁移或不可逆转换，实施前明确备份、恢复或前向修复方案及可接受的数据损失；备份是否有效需要恢复证据支持。
7. 发布顺序和应用回退条件遵循[发布与回退](../operations/AGENTS.md#发布与回退)。应用回退、结构回退和数据恢复是不同操作，不假定回退应用就能撤销数据变化。

## 缓存

- 明确缓存对应的权威来源、更新方式、失效条件、最长陈旧时间及故障时行为。
- 缓存键包含会影响结果的租户、权限或版本上下文，防止不同用户间错误复用数据；敏感结果需要特别评估是否可缓存。
- 设置容量和淘汰策略，按需求应对集中失效、热点键和不存在数据的重复查询，不为小规模场景提前堆叠复杂机制。
- 不使用进程内缓存保证跨实例唯一性、库存或资金正确性；需要协调时采用与一致性目标匹配的存储机制。
- 更新数据库和缓存的顺序存在并发窗口，应根据业务允许的陈旧程度选择策略，并验证失败后的恢复过程。

## 文件与对象存储

- 明确路径、对象键、访问权限、大小上限和清理策略，输入校验遵循[不可信输入](../security/AGENTS.md#不可信输入)。
- 写入重要文件时考虑中断和部分写入；在目标文件系统支持时使用同一文件系统内临时写入后原子替换，并按持久性要求处理刷盘。远端对象存储遵循自身语义，不照搬本地重命名假设。
- 清理、覆盖或递归删除前核对实际作用范围；保护任务范围外的数据，处理符号链接和 Windows 重解析点等可能改变目标的情况。
- 用户上传、导出文件和备份都受数据保留与隐私要求约束。开发临时文件的位置与生命周期分别遵循[工作区布局](../workspace/AGENTS.md)和[测试临时目录](../testing/AGENTS.md#测试临时目录)。
