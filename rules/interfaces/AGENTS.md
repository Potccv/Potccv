# AGENTS.md — 接口与集成

使用本资料设计或修改模块公共接口、HTTP API、RPC、消息事件或外部系统集成时，遵循本文件及[根目录执行要求](../../AGENTS.md)。维护本目录文档时，同时遵循[通用约定文档的维护要求](../AGENTS.md)。

先掌握[契约与边界](#契约与边界)和[兼容性](#兼容性)，网络调用、批量查询与消息系统再选读对应章节；不把分布式系统要求套到没有这些边界的本地函数。

## 契约与边界

- 公共接口应明确用途、输入、输出、副作用、错误、权限、单位和限制；按项目现有方式维护类型、Schema、IDL 或接口说明，不手工维护相互矛盾的多份契约。
- 在边界验证输入结构、大小、必填项、取值范围及字段间关系；未知字段是拒绝、忽略还是保留，应结合兼容策略明确约定。
- 区分字段未提供、显式 `null`、空字符串和空集合的含义，尤其是局部更新接口；不根据实现便利随意覆盖用户已有数据。
- 对外仅暴露必要字段，不直接序列化内部模型、数据库实体或异常对象。请求到内部对象的映射采用允许字段清单，避免调用方修改不该修改的属性。
- HTTP 接口遵循方法和状态码语义：读取不产生调用方未预期的业务写入，已接收的异步任务不能被表述为已经完成。
- 调用外部系统时，验证响应结构和业务状态；收到 HTTP 成功码不必然意味着业务成功，格式正确也不代表内容可信。

## 兼容性

- 修改契约前识别消费者，包括旧客户端、脚本、第三方、持久化消息和混合版本服务；不能只检查当前仓库里的最新调用方。
- 新增必填字段、移除或改名字段、改变字段类型、枚举、排序、错误语义及默认行为，都可能构成破坏性变更。
- 新增可选字段通常更易兼容，但仍须考虑严格解析器、签名校验和代码生成器；以真实消费者验证兼容性，不仅凭经验判断。
- 必要时采用兼容读取、双版本接口或分阶段迁移，明确弃用窗口、迁移指引和移除条件；不因改动很小就省略迁移安排。
- 保持稳定的业务标识和错误码；文字描述可以改善，但不能要求客户端通过匹配一段人类可读消息来判断业务状态。

## 错误契约

- 向调用方提供稳定的错误分类、可理解的说明和必要的关联标识；内部堆栈、SQL、密钥和敏感个人数据不得出现在外部错误中。
- 区分输入无效、未认证、无权限、资源不存在、冲突、限流和服务故障；避免所有失败都返回同一个成功状态码。
- 只有确实可恢复的失败才标记可重试；“未知是否成功”必须保留该语义，不得简单宣称操作未发生。
- 批量操作明确采用全部成功或逐项结果；允许部分成功时，提供每项结果及安全重试方式。
- 根据威胁模型决定是否合并某些错误，避免通过登录、找回密码等响应泄露用户或资源是否存在。

## 超时重试与幂等

- 所有跨进程调用应有有限的超时；按实际需求区分连接、读取与总截止时间。子调用不能不断重新获得完整时间预算。
- 只重试可恢复错误和能够安全重复的操作；结合总时间预算、次数上限、退避与随机抖动，遵循服务端合理的限流提示。
- 在明确的层级执行重试，避免客户端、网关和服务端各自重试造成请求放大。无可行恢复动作时，直接返回可识别的失败。
- 对付款、建单等不能重复执行的操作，幂等键应绑定调用方或租户、操作类型及请求内容，并明确有效期、并发处理和结果保存规则。
- 幂等记录与业务效果需要满足相应一致性要求；仅在内存中缓存一个请求 ID，不能保证进程重启或多实例情况下不重复执行。
- 超时和取消可能发生在写入已成功之后。重试前可按业务标识查询结果，或沿用同一幂等键；不能换一个新键盲目重试。

## 分页与批量处理

- 为返回条数、批量大小、请求体和处理时长设置适用的边界，避免一次请求读取或处理无限数据。
- 分页必须采用稳定排序，并在必要时以唯一字段打破并列；说明数据变化期间是否可能重复或遗漏。
- 大规模或持续变化的数据可采用游标分页；游标要校验合法性，并限制在当前查询及权限范围内。偏移分页适合其成本可接受的场景。
- 明确筛选、搜索和排序允许的字段；不得将用户输入直接拼接成数据库表达式。
- 长任务按需要提供任务状态、取消、分片或进度查询，避免把完整处理过程强塞进短时交互请求。

## 消息与事件

- 区分命令和已经发生的事件，明确生产者、消费者、业务标识、事件版本和必要的时间语义。
- 根据消息系统的真实保证处理重复、乱序、延迟和重新投递；不得把“至少一次投递”当成“业务只执行一次”。
- 明确消息确认时机及失败恢复方式，避免确认过早导致丢失；消费者需要时采用幂等处理、去重记录和有界重试。
- 说明顺序保证的范围，例如单个订单或分区，而非笼统宣称全局有序。
- 对无法自动处理的消息设置隔离、告警和受控重放流程，保留必要诊断信息并按[安全与隐私](../security/AGENTS.md)处理敏感内容。
- 数据库写入与发消息需要协调时，按[事务与并发一致性](../data/AGENTS.md#事务与并发一致性)选择方案；不得假定两个系统会一起成功。

接口变更的验证应覆盖消费者兼容、错误路径、超时和重复请求中实际受影响的部分，具体见[测试与验证](../testing/AGENTS.md#验证范围)。
