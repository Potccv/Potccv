# AGENTS.md — 编码与测试

本文件补充[开发协作要求](../AGENTS.md)，用于项目启动、源码开发、测试与 demo 交付任务。

## 工作区布局

- 使用本约束开始项目前，先在当前工作区内建立与工作区同名的子目录，作为待推送到 GitHub 的项目目录；已有同名目录时沿用。所有计划推送的内容都放入该目录，包括源码、项目文档和必要配置。
- AI 应根据项目与当前任务的实际需要，在工作区内按需建立开发与测试目录，优先沿用已有合适目录；确有对应内容需要存放时才创建，并与待推送目录同级。下表仅列出可选目录示例。

| 可选目录 | 创建条件与用途 |
|---|---|
| `tmp/` | 需要保存开发临时文件、测试临时文件或临时打包文件时 |
| `build/` | 需要保存编译、构建或交付产物时 |
| `data/` | 需要保存开发、测试或运行数据时 |
| `doc/` | 需要保存本机开发、测试或交付资料时，分类见[资料存放位置](../doc/AGENTS.md#资料存放位置) |

- 开发与测试使用或生成的临时文件、日志、数据、缓存、构建产物、tarball 和备份均须保存在当前工作区内，禁止放到系统临时目录、工作区外的同级目录或其他位置。启动相关工具前，将其临时目录、输出目录和相关缓存目录配置到工作区内；备份保留策略沿用项目自身约定。
- 个人配置与凭据按[凭据与发布要求](../../../profile/AGENTS.md#凭据与发布)单独管理。

## 测试临时目录

- 测试需要临时文件时，在[工作区布局](#工作区布局)约定的临时文件目录内为本次测试新建专用子目录，按 `YYYYMMDD-HHmmss-测试内容` 命名；日期时间采用创建时的本地时间，测试内容使用简短、可识别的描述，例如 `20261005-153000-接口冒烟测试`。
- 测试通过后，按[文档与资料要求](../doc/AGENTS.md)保存必要的验证记录，并及时删除本次测试的临时目录及其中的文件。
- 需要用户手动删除的目录统一加 `!` 前缀，便于按名称升序排列时优先显示；测试已通过的目录同时加 `-PASS` 后缀，命名为 `!原目录名-PASS`，例如 `!20261005-153000-接口冒烟测试-PASS`。已有前缀或后缀时不重复添加。
- 测试通过后的删除操作若被自动拦截，按上述方式标记目录，并告知用户测试已通过但清理未完成，提供实际目录路径，提醒用户手动删除。若重命名也被拦截，保留原名并如实报告实际路径及未能标记的情况。

## 开发与验证

- 条件允许时，先在本地验证，再到获准的测试设备核验实际运行情况。
- 涉及 UI 的测试应在用户协作下完成。
- 版本与提交遵循 [Git 要求](../../git/AGENTS.md)。
- 验证结果按[文档与资料要求](../doc/AGENTS.md)记录。

## demo 交付

- 用户要求生成 demo 时，默认构建整个项目，交付完整项目编译后的产物供用户测试；只有用户明确指定仅包含哪些功能时，才按其指定范围生成 demo。
- 产物存放遵循[工作区布局](#工作区布局)。交付时说明产物路径、运行方式及实际验证结果。
